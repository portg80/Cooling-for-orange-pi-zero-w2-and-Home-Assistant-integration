

# Описание скриптов для подготовки датасета wake word «Афина»



## `more_positive_speakers_modulyator_v5.py`



Скрипт делает аугментации звуковых дорожек — позитивных примеров wake word.



Основная задача скрипта — привести оригинальные записи wake word «Афина» к заданной длительности фразы.  

В моём случае это **2 секунды**.



Если оригинал длиннее заданного времени — скрипт обрезает его.  

Если короче — дополняет, но **не нулями**, а тихим шумом из папки `low_noise`.



Папки с тихим шумом задаются в переменной:



```python

LOW_NOISE_DIRS

````



Оригинал обычно вставляется по центру с рандомным смещением в миллисекундах.

Также можно зафиксировать вставку к началу или к концу через параметр:



```python

crop_mode

```



Во время участка речи `low_noise` приглушается на заданное значение:



```python

LOW_NOISE_UNDER_SPEECH_RATIO

```



Это нужно, чтобы фон звучал реалистично, но не мешал речи.



Границы речи определяются через `silero_vad` — начало и конец фразы.

Это помогает корректнее размещать фразу внутри 2 секунд и не отрезать атаки, согласные и другие важные части слова.



Также есть `trim` / подчистка тишины по краям.

Это особенно полезно для TTS-записей.



### Аугментации



Скрипт создаёт следующие варианты:



* `Pitch shift` — изменение тональности, варианты берутся из массива `PITCH_SHIFTS`.

* `Reverb` — реверберация через impulse response из папки `IR_DIR`.

* `Aggressive noise` — агрессивный шум: музыка, машины, улица и так далее, из папок `AGGRESSIVE_NOISE_DIRS`.



### Наложение агрессивного шума



При наложении агрессивного шума:



* берётся RMS основной дорожки;

* шум подгоняется по громкости относительно основной дорожки;

* общий уровень задаётся множителем `LOW_NOISE_MULTIPLE_VOLUME_DOWN`;

* дополнительные уровни «тишины» задаются массивом `AGGRESSIVE_NOISE_MULTIPLE_VOLUME_DOWNS`;

* сколько значений в `AGGRESSIVE_NOISE_MULTIPLE_VOLUME_DOWNS`, столько вариантов шума создаётся на один оригинал;

* `AGGRESSIVE_NOISE_PASSES` позволяет сделать несколько прогонов, при этом шумы каждый раз выбираются случайно.



### Комбинированные варианты



Также создаются комбинированные аугментации:



* `pitch + reverb`;

* `pitch + aggressive noise`.



### Важно



Использованные 2-секундные отрезки агрессивного шума сохраняются в соседнюю папку:



```text

aggressive_noise_used_for_negative

```



Это удобно использовать позже как **negative dataset**.



Перед запуском скрипт показывает расчёт:



* сколько будет новых файлов;

* сколько часов получится по каждой папке.



После этого скрипт просит подтверждение и только потом начинает генерацию.

## `select_negatives_balanced_windows_ru_with_existing.py`



Скрипт нарезает негативы на фиксированные сегменты.



В моём случае:



```python

SEGMENT_SEC = 2.0

```



То есть нарезка идёт по **2 секунды**.



Скрипт используется для подготовки негативного датасета:



* музыка;

* подкасты / YouTube;

* бытовые шумы;

* атмосфера;

* важные записи речи.



### Главная идея



Из каждого аудио берётся понемногу — порциями, то есть окнами.



Если нужно больше длительности, чтобы достичь цели по часам, текущая длина окна рассчитывается автоматически.



Чтобы категории не исчезали из-за неравномерной длительности треков, скрипт не отбрасывает файлы целиком вслепую.



Вместо этого он:



1. Берёт из каждого файла несколько окон, например `3` окна.

2. Распределяет окна равномерно по треку.

3. Добавляет рандомный сдвиг — `jitter`.

4. Нарезает эти окна на 2-секундные сегменты.



Так длинные подкасты не съедают весь датасет, а музыка и короткие звуки не пропадают полностью.



### Что настраивать



* `TARGET_NEG_HOURS` — сколько часов негативов нужно получить в итоге после нарезки.

* `SEGMENT_SEC` — размер сегмента для нарезки, обычно `2` секунды.

* `CATEGORIES` — список категорий записей, например музыка, шум города и так далее.



Для каждой категории можно настроить:



* `mode="full"` — брать файлы целиком. Обычно используется для важных речевых категорий.

* `mode="windowed"` — брать по окнам. Обычно используется для длинных треков.

* `windows_per_file` — сколько окон брать из каждого файла. Можно переопределить на уровне категории.

* `min_window_sec` — минимальная длина одного окна, чтобы не набрать случайные 2 секунды.

* `tail_policy`:



  * `"drop"` — хвост меньше 2 секунд отбрасывается. Обычно используется для музыки и шумов.

  * `"pad_noise"` — хвост дополняется `low_noise`, а не нулями. Важно для речи.

* `sacrifice=True` — если цель слишком маленькая, то при урезании объёма сначала выкидываются файлы из этих категорий.



### Учёт уже нарезанных файлов



Если уже есть готовые 2-секундные негативные сегменты, их можно включить в расчёт.



Тогда скрипт будет добирать только недостающий объём.



За это отвечают параметры:



* `COUNT_EXISTING_IN_OUTPUT_ROOT` — учитывать уже лежащие сегменты в `OUTPUT_ROOT`;

* `COUNT_EXISTING_IN_DIRS` + `EXISTING_SEGMENTS_DIRS` — учитывать сегменты в любых других папках.



То есть `TARGET_NEG_HOURS` — это цель с учётом уже имеющихся сегментов.



### Куда пишет



Все данные складываются в:



```python

OUTPUT_ROOT

```



Внутри создаются папки по названиям категорий.



Служебная папка:



```text

OUTPUT_ROOT/_cache_meta

```



Она используется для кэша метаданных и ускоряет повторные запуски.



### Отчёты



Скрипт создаёт отчёты:



* `selection_summary.json` — общий план и статистика;

* `selection_details.csv` — какие окна и куски откуда брались.



### Как запускать



1. Заполнить `CATEGORIES` — пути к папкам.

2. Указать `TARGET_NEG_HOURS`, `SEGMENT_SEC` и параметры окон глобально или по категориям.

3. Запустить скрипт.

4. Скрипт сначала посчитает план, покажет предупреждения и спросит подтверждение, если `ASK_CONFIRMATION=True`.

5. После подтверждения начнёт нарезку и сохранение.

## `translit_RU_bukvi_to_ENG.py`



Скрипт рекурсивно проходит по указанной папке и переименовывает файлы.



Например:



```text

Привет мир 123.wav

```



будет переименован в:



```text

Privet_mir_123.wav

```



Это нужно, чтобы в дальнейшем не было ошибок из-за кириллицы, пробелов и лишних символов в именах файлов.
